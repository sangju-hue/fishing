# 서해 쭈꾸미 예약 현황

웹페이지는 [GitHub Pages](https://sangju-hue.github.io/fishing/)에서 실행하고, 예약 현황 수집과 데이터 업로드는 맥에서 실행한다. GitHub Actions의 기존 `scrape.yml` 수집 작업은 비활성화했다. Pages 배포 작업은 유지한다.

## 수집 범위

- 서해 군산까지의 선사. 군산보다 남쪽의 전남·경남·부안 지역은 쭈꾸미 명부에서 제외한다.
- 매년 9월 1일~11월 30일. 한국 시간의 **오늘 이후만** 갱신한다. 지난 날짜의 같은 시즌 데이터는 보존한다.
- 12월부터는 다음 해 시즌을 조회한다. 월 단위 조회만 제공하는 사이트는 해당 월 응답을 받되 오늘 이전 행은 갱신하지 않는다.
- 한 선단의 여러 배는 예약표의 실제 배 이름과 선박 ID로 구분한다. 같은 이름이라도 출항 항구가 다르면 별개로 취급한다.
- 여러 출조가 있는 날의 잔여석은 예약 가능한 **단일 출조의 최대 잔여석**이다. 오전·오후 인원을 합산하지 않는다.
- 접속 성공만으로 수집 성공으로 처리하지 않는다. 잔여석을 읽을 수 없으면 미확인으로 유지하며, 승선자 명단의 인원으로 추정하지 않는다.

오천항·영흥도·무창포항을 우선 대조했다. `data/catalog_audit.json`에 추가/수정 항목, 항구 확인 근거와 미확인 항목이 기록되어 있다. 명부의 항구는 개별 배의 출항 항구다. 화면의 **기타** 메뉴는 등록 수 1~2척인 항구를 묶는 표시이며 실제 항구 정보를 바꾸지 않는다. 출항지를 확인하지 못한 배는 ‘항구 확인 중’이다.

쭈꾸미·우럭·갈치·문어 탭이 있으며, 우럭·갈치·문어는 추후 데이터 추가를 위한 준비 화면이다.

## 맥에서 실행

Python 3 표준 라이브러리만 사용한다.

1. 이 폴더의 `.github_token`에 저장소 쓰기 권한이 있는 GitHub 토큰을 저장한다. 토큰은 맥에서만 사용하며 웹페이지와 게시 데이터에는 포함하지 않는다.
2. 한 번 수집하고 업로드하려면 `bash fishing.sh`를 실행한다.
3. 자동 실행은 `python3 install_mac_scheduler.py`로 등록한다. 로그인 시 `com.sam.fishing-scrape` LaunchAgent가 시작한다.

기본 주기는 **5분**이다. 웹페이지에서 1분·5분·10분·30분·1시간 중 선택하고 ‘맥에 적용’을 누르면 이 맥의 설정 서버(`127.0.0.1:8788`)에 저장한다. 수집기를 실행하지 않는 기기에서는 주기를 변경할 수 없다. 브라우저가 로컬 네트워크 연결 권한을 요구할 수 있다.

한 번 수집이 선택한 주기보다 길어져도 이전 수집과 겹쳐 실행하지 않는다. 따라서 1분 옵션이 매분 전체 수집 완료를 보장하지는 않는다. 로그는 `scrape.log`, 설정은 `scrape_settings.json`에 저장한다. 변경된 데이터 파일만 GitHub에 원자적으로 게시한다.

## 주요 파일

| 파일 | 역할 |
|---|---|
| `index.html` | GitHub Pages 웹페이지 |
| `data/boats.json` | 배·선사 명부, 출항 항구, 예약 채널, 확인 근거 |
| `scrape_sunsang24.py` | 선상24 월별 예약 현황 |
| `scrape_homepages.py`, `collect_homepages.py` | 등록 홈페이지의 예약 메뉴 탐색·수집 |
| `homepage_engine.py` | 예약표 파싱·선박 이름 확인·출조별 집계 |
| `season.py` | 한국 시간 기준 조회 기간 |
| `data/status.json`, `data/status_homepages.json` | 날짜·선박 ID별 예약 상태 |
| `data/site_health.json` | 홈페이지 수집 결과·오류·미수집 배 |
| `mac_scheduler.py`, `run_collection.py` | 주기 변경·중복 실행 방지 |
| `push_to_github.py` | 명시한 공개 파일만 게시 |
| `audit_catalog.py`, `audit_ports.py`, `verify_catalog.py`, `reconcile_catalog.py` | 수동 명부 감사 도구. 정기 수집에서 실행하지 않음 |

점검: `python3 -m unittest discover -s tests -v`

접속 차단·폐쇄·예약표 미제공·개명 여부 불명확한 사이트는 실제 예약 상태를 확정할 수 없다. 그런 경우 ‘홈페이지 없음’으로 단정하지 않고 예약 미확인으로 표시한다. `diagnostics/`의 원본 페이지와 승선자 정보는 게시 대상이 아니다.

## 예약표 안내 문구 수집 기준

- 각 선박의 각 날짜 예약표에서 ‘상황에 따라/개인사정’과 ‘예약 오픈’ 안내가 함께 있으면 `conditional` 상태로 수집한다. 날짜칸에는 주황색 **유동**으로 표시하고 원문 안내를 보존한다. 특정 날짜에 한정하지 않고 매 수집 시 모든 조회 날짜에 적용한다.
- 예: ‘선장님 개인사정으로 2026년도 쭈갑예약은 상황에 따라 오픈합니다.’ 같은 안내는 마감이나 미확인으로 분류하지 않는다. 안내가 사라지고 잔여석이 공개되면 다음 수집에서 일반 예약 상태로 갱신한다.
- 공지와 선박 이름·예약 날짜가 일치하는 경우에만 적용한다. 시즌 종료·다음 해 인사는 별도 시즌 안내로 표시하며, 일반 기상 취소와 구분한다.
